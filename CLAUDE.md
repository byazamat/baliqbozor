# CLAUDE.md — инструкция для AI-агента

## Проект

**BaliqBozor** (рабочее название) — B2B-маркетплейс рыбы для рыбных хозяйств Узбекистана: покупатели (рестораны, магазины, оптовики) размещают заявки, рыбхозы отвечают предложениями, оператор собирает сборные заказы и назначает перевозчиков, стороны фиксируют фактический вес при приёмке, расчёты и рейтинги.

Полное ТЗ: **`docs/SPEC.md`** — единственный источник истины. Прочитай его целиком перед началом работы и перечитывай нужный раздел перед каждой задачей.

## Как работать

1. Работай строго по milestones из `docs/SPEC.md`, раздел 14.1, по порядку. Не начинай следующий milestone, пока текущий не соответствует критерию готовности.
2. Перед каждым milestone составь план задач и запиши его в `docs/PROGRESS.md` (чек-лист). Отмечай выполненное.
3. Если требование неоднозначно — возьми значение по умолчанию из раздела 15, реализуй его как настройку и запиши решение в `docs/DECISIONS.md` (дата, вопрос, решение, причина). Не останавливайся ради вопросов, которые закрываются этим правилом.
4. Не реализуй то, что в разделе 1.4 «Вне объёма MVP». Для будущих модулей создавай только интерфейсы провайдеров из раздела 16, если они нужны текущему коду.
5. Не меняй смысл модели данных, статусов и правил из разделов 7–9. Добавлять индексы, служебные поля и обратные связи Prisma можно.
6. Маленькие, проверяемые шаги: после каждой законченной части — тесты, линтер, typecheck.

## Команды

```bash
pnpm i
docker compose -f infra/docker-compose.yml up -d   # Postgres, Redis, MinIO
pnpm db:migrate                                     # prisma migrate dev
pnpm db:seed
pnpm dev                                            # все приложения (turbo)
pnpm test                                           # unit + e2e
pnpm lint && pnpm typecheck
pnpm api:generate                                   # OpenAPI → packages/api-client
```

Если какой-то команды ещё нет — создай её в корневом `package.json` в M0.

## Обязательные правила кода

- TypeScript strict; без `any`; без `// @ts-ignore` без комментария-обоснования.
- **Деньги** — только целые суммы в `BigInt`, в API — строки. Никаких `number`/`float` для денег. **Вес** — `Decimal(12,3)`, расчёты через `decimal.js`. Округление денег — до целого сума, половина вверх.
- **Время** — UTC в БД; даты поставки и окна вылова — тип `date`; отображение — `Asia/Tashkent`.
- **Бизнес-логика** (статусные машины, суммы, комиссии, скоринг подбора, свежесть, надёжность) — чистые функции в `packages/domain` с модульными тестами. Сервисы NestJS их вызывают.
- **Изоляция организаций:** каждый запрос к данным организации проходит guard членства (`X-Org-Id`) и политику доступа к ресурсу. Продавец не видит чужие строки сборного заказа, перевозчик не видит цены. На каждый ресурс — e2e-тест изоляции.
- **Резервирование объёма** — только в транзакции с блокировкой строки наличия (`SELECT … FOR UPDATE`).
- **Доменные события** пишутся в `DomainEvent` в той же транзакции, что и изменение; уведомления и realtime — только из worker по outbox.
- **Строки интерфейса** — только ключи i18n (`packages/i18n`), всегда в обоих языках (uz, ru).
- **Ошибки API** — единый формат и коды из `packages/domain/errors.ts`.
- **Миграции** — `prisma migrate dev --name <осмысленное_имя>`; применённые миграции не редактировать.
- **Секреты** — только env; поддерживай `.env.example` актуальным.
- **Логи** — без персональных данных; телефоны маскировать.
- **Коммиты** — Conventional Commits.

## Definition of Done

Смотри `docs/SPEC.md`, раздел 14.2. Кратко: тесты (unit для домена, e2e для эндпоинтов, включая права и изоляцию), OpenAPI и клиент обновлены, i18n в двух языках, миграция проверена, аудит и доменные события добавлены, `PROGRESS.md` обновлён, CI зелёный.

```

packages/i18n   Переводы и форматирование
```

## Чего не делать

- Не подключать онлайн-платежи, e-baliq, IoT, учёт хозяйства, B2C — это вне MVP.
- Не хранить ПИНФЛ и другие лишние персональные данные.
- Не использовать Expo для мобильного приложения (только React Native CLI).
- Не делать OTP-обход вне `APP_ENV=local`.
- Не отправлять уведомления напрямую из HTTP-обработчиков — только через outbox и worker.
