# Принятые решения

Формат: дата · вопрос · решение · причина. Заполняется по ходу разработки (см. SPEC.md, раздел 15).

- **D-01** · 2026-10-31 · Node 20 LTS из SPEC 5.2 · Node 24 LTS (`.nvmrc`, `engines`) · Поддержка Node 20 закончилась в апреле 2026.
- **D-02** · 2026-10-31 · React 18 / Next 14+ · Next.js 15+/16 и React 19 во всех приложениях, одна версия React в монорепозитории · Актуальный React Native требует React 19; две мажорные версии React в одном pnpm-монорепозитории часто ломают сборку.
- **D-03** · 2026-10-31 · Prisma 5 из SPEC 7.1 · Последняя Prisma 6.x · Схема 7.2 проходит без правок; в Prisma 7 изменён `datasource url`. Переход на 7 — отдельным решением.
- **D-04** · 2026-10-31 · Когда вводить схему БД · Полная схема 7.2 и миграция `init` в M0 · Нужна для проверки `prisma migrate diff` в CI; смысл схемы зафиксирован ТЗ.
- **D-05** · 2026-10-31 · Пути health (5.3 против префикса 10.1), health у worker · `/health` и `/ready` вне `/api/v1`; worker поднимает HTTP-сервер на `WORKER_HEALTH_PORT` · Привычно для проб оркестратора; у standalone-worker нет HTTP.
- **D-06** · 2026-10-31 · Mobile в `pnpm dev` и CI · Не входит в `pnpm dev` (скрипты `mobile:*`); в CI только typecheck + jest · Нативная сборка долгая и требует SDK/Xcode.
- **D-07** · 2026-10-31 · Hoisting зависимостей для RN · `node-linker=hoisted` или точечный `public-hoist-pattern` — выбор по результату проверки Metro в M0.11 · Metro плохо работает с симлинками pnpm.
- **D-08** · 2026-10-31 · i18n-библиотеки · `packages/i18n` хранит JSON и форматтеры; web/admin — next-intl, mobile — i18next · ТЗ не задаёт библиотеку; общий источник ключей сохраняется.
- **D-09** · 2026-10-31 · Форматирование денег, веса и дат · Свои форматтеры без `Intl` · В Hermes `Intl` ограничен, локаль `uz` неполная; вывод должен совпадать на Node, в браузере и на Hermes.
- **D-10** · 2026-10-31 · Недостающие переменные окружения · Добавить `S3_PUBLIC_ENDPOINT`, `JWT_ACCESS_SECRET_PREVIOUS`, `WORKER_HEALTH_PORT`, `APP_DEEPLINK_SCHEME=baliqbozor`, `BRAND_NAME` · Presigned URL для браузера, ротация JWT двумя ключами (13.2), бренд и схема в конфиге (15.11).
- **D-11** · 2026-10-31 · Ожидающие приглашения (8.1) без модели · Новая модель `OrgInvitation(phone, orgId, role, invitedById, expiresAt, acceptedAt)` в M1 · Иначе требование 8.1 не реализовать.
- **D-12** · 2026-10-31 · Порядок milestones против зависимостей · Минимальные outbox, in-app уведомления, settings и загрузка медиа (presigned + complete) переносятся в M1; обработка медиа остаётся в M2 · Критерий M1 требует отправки документов и in-app уведомления, а M2 — напоминаний о свежести.
